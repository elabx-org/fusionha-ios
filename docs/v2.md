# fusionha v2

v2 is a second app built from this repo and installed beside v1. v1 keeps
shipping, unchanged, while v2 is rebuilt screen by screen from the approved v2
mock (owner, 2026-11-05). Both apps come from `main` and ship in the same
Feather source.

## The two products

| | v1 | v2 |
|---|---|---|
| Home-screen name | fusionha | fusionha v2 |
| Scheme / target | `Fusionha` | `FusionhaV2` |
| Bundle ids | `org.elabx.fusionha`, `.widgets`, `.notification-service` | `org.elabx.fusionha.v2`, `.v2.widgets` (`.v2.notification-service` comes with push) |
| App Group | `group.org.elabx.fusionha` | `group.org.elabx.fusionha.v2` |
| Keychain group | `$(AppIdentifierPrefix)org.elabx.fusionha.shared` | `$(AppIdentifierPrefix)org.elabx.fusionha.v2.shared` |
| Keychain services | `org.elabx.fusionha.*` | `org.elabx.fusionha.v2.*` |
| URL scheme | `fusionha://` | `fusionha2://` |
| Version | 1.1.<CI run> | 2.0.<CI run> |
| Icon | `AppIcon` | `AppIconV2` (`scripts/make_v2_icon.py`) |
| Push | on | off (see below) |

Each app signs in on its own. Signing out of v2 never touches v1: v2 has its own
App Group, its own keychain services, and no `TEAMID.*` wildcard keychain group
(only v1 keeps that legacy fallback).

## How the code is split

- **`AppIdentity`** (`Packages/FusionhaKit/Sources/FusionhaKit/AppIdentity.swift`)
  reads `FusionhaAppGroup`, `FusionhaKeychainNamespace` and `FusionhaURLScheme`
  from the running bundle's Info.plist. A missing key falls back to v1's value,
  so v1's Info.plists don't carry the keys. Every App Group, keychain service,
  team keychain group and deep link comes from it, never from a literal.
- **Entry points.** `App/FusionhaApp.swift` (v1) and `App/V2/FusionhaV2App.swift`
  (v2) are the only `@main`s. Both wrap `AppSceneContent`: the screenshot
  galleries, sign-in gate, Duo harness, deep links and probes. v1 passes
  `RootView`, v2 passes `V2RootView`.
- **Targets** (`project.yml`). The v1 targets exclude `App/V2/**` and
  `Widgets/V2/**`. `FusionhaV2` compiles `App` (without `FusionhaApp.swift`)
  and `Shared`. `FusionhaV2Widgets` compiles `Widgets` and `Shared`. Both v2
  targets build with the `V2` compilation condition. Keep `#if V2` to a few spots
  in shared code. v2 screens are new files under `App/V2/` that reuse v1's
  stores and models.
- **Push.** The server sends every push under v1's topic, and APNs rejects v2's
  tokens under it. So v2 has no notification-service extension and no
  `aps-environment`. Under `V2`, `PushRegistration.register` returns nil and
  `AppDelegate` neither asks for notification permission nor registers with APNs.
  v2's API token is named `fusionha v2 iOS · <device>` so the server's token
  list tells it apart from v1's.
  This changes once the server accepts a per-device topic (slice S16).

## Shipping

CI builds both schemes as a matrix (`.github/workflows/build.yml`). A separate
`release` job publishes `build-N` with `Fusionha.ipa`, `FusionhaV2.ipa` and one
`source.json` (`scripts/release_source.sh` → `scripts/make_source.py`). v1 is
required. If the v2 leg fails, the job carries v2's entry over from the previous
release's source.json, so v2 stays listed in Feather. The source's identifier and
URL don't change.

The screenshots, iPhone Duo and perf jobs build only the v1 scheme for now.

Before the first install, the owner registers the v2 App IDs and the
`group.org.elabx.fusionha.v2` App Group on the developer account.

## Visual system (slices S1 and S2)

- **Badge state** (`FusionhaKit/EditionBadgeState.swift`): on disk / partial
  (n of m) / missing / downloading (progress) / held, from a coverage `Rail`
  plus the version's `QueueProgress`, or from a wire `EditionStatus`.
  Upgrading reads as downloading; attention, dead links and held imports read
  as held. `EditionBadgeState.joins` (both on disk or both missing) decides
  the spoken pair; the drawn pair joins when both halves draw alike with
  nothing beside them, so with counts hidden partial joins on disk.
  `EditionBadgeSpeech` gives VoiceOver its words.
- **Badges** (`Shared/Design/Badges/`): A1 monochrome T5 tickets. `TicketPiece`
  is the scalloped half (three shallow 0.9pt quadratic scallops, so the 2pt
  joined seam stays open and never reads as "$"), `EditionTicketPair` the
  HD/4K pair (joined or apart),
  `EditionBadge` a single version, `DownloadRing` the ring. They draw in a
  `BadgeInk` (`Shared/Design/BadgeInk.swift`): `.page` (any palette),
  `.tinted(ink:ground:)` for art-tinted pages, `.onArt` over artwork, set with
  `.badgeInk(_:)`. They live in `Shared` so v2's widgets can use them; v1
  never does, so v1 looks the same.
- **Rails** (`App/V2/Components/Rails/`): one ink, from `OneInkRail`.
  `RailBarV2` (season capsule or download progress), `EpisodeTicks` (one tick
  per episode up to 26, or the capsule when the row is too narrow) and
  `StorageCapsule` (stacked storage bar and legend). Held is the palette's
  `stuck` in rails as well as badges: one orange, where the mock's rails use
  #FF9F0A / #FF9500 (deliberate). On the achromatic palettes (OLED, Noir,
  Monochrome, `BadgeInk.patterned`) the accent and held inks sit on the
  on-disk grey, so rails draw downloading as accent hatching on the track and
  held as a held-ink outline.
- **Art palette maths** (`FusionhaKit/PaletteMath.swift`): RGB↔HSL, 12 hue
  buckets weighted by vividness, the top three, the dark and light lift
  clamps, and the page tints. Slice S3 adds the extractor and the ground (below).
- **Badge gallery**: Account (or You) › fusionha v2 › Badge gallery, in v2's
  Release builds too. It shows every state on every palette, at the default
  size and at a large Dynamic Type size, plus the joined/apart animation.

## Art palette ground and W1 cards (slice S3)

- **Extractor** (`App/Components/Images/ArtPaletteExtractor.swift`): an actor.
  It takes the art through `ImagePipeline` (the w780 copy the hero's ambient
  already loads, `ArtPaletteExtractor.sampleURL`), stretches it into a 40×40
  sRGB bitmap off the main thread, and keeps `PaletteMath.dominant`'s three
  colours *before* the lift in an NSCache plus a small JSON disk cache
  (Caches/ArtPalette, one file per URL hash). The lift runs per palette, so a
  palette switch never re-reads the art. "Reset cache & reload" clears it.
- **Page palette** (`Shared/Design/PagePalette.swift`): `\.pagePalette`
  carries the ground recipe, the page tints (the mock's --tint / --tint2), the
  text inks (--tintink / --tintmut) and the badge ink (`BadgeInk.tinted`).
  With no art it is built from the palette's tokens. Hue-less palettes
  (Monochrome, Noir, OLED: `PagePalette.dropsHue`) lift with s = 0, so their
  grounds stay grey.
- **Ground** (`App/V2/Components/Ground/`): `PageGround` draws
  `FusionhaKit/PageGroundRecipe` (a base in the lifted art colours, never
  the page's near-black, under four soft ellipses reaching every corner;
  OLED and Noir `deep`: dark but tinted; `.page` and the deeper `.listPane`
  for the open Duo's list), plus the art itself blurred across the top (the
  Library's ambient layers screen-blend on dark palettes, so a dark side of
  the art never blacks out that side of the page) (`ArtBlurSpec.pageGround`: blur 46, saturate
  1.7, a cached bitmap, no live blur). No art: the token tint ground
  (cards-w.js `.w1-tint`, from i1 / grab / edition). Pages call
  `.v2PageGround(art:)`; `PageArtSource` / `V2Page.groundSource` is the
  mock's `GROUND` map of which art each page uses.
- **W1 cards** (`App/V2/Components/Cards/`): `.v2CardStyle()` and
  `WidgetModule` (caption inside, rows split by hairlines). Ultra-thin
  material plus the mock's wash (rgba(30,30,38,.40) dark, white .58 light),
  a 0.5pt top light edge, 22pt corners, no stroke, and one pre-blurred
  nine-slice shadow with the card cut out of it, so it never darkens the
  translucent card. This is material, not Liquid Glass (owner, 2026-11-05).
- **Ground preview**: Account (or You) › fusionha v2 › Ground preview: any
  library title's ground (or the tint ground), in any palette, page or list
  pane, with modules on it, and three titles side by side.

## Library tab (slice S4)

- **Wiring**: `V2RootView` passes `V2LibraryView` as the Library tab's root
  (`\.libraryTabRoot`, `App/Screens/Library/LibraryTabRoot.swift`; v1 never
  sets it, so v1 still shows `LibraryView`). Every other tab is v1's, and a
  tapped title still opens v1's title page.
- **Reused from v1**: the model's library and loading, `LibraryInputs`
  (filtering, counts, rows), the persisted filters under v1's keys, the A–Z
  scrubber, the poster sheet (press and hold), the select bar (system bottom
  bar, Monitor on a bookmark) and the stats sources (`StatsSheetFeed`).
- **Screen** (`App/V2/Screens/Library/`): on the S3 ground from the
  Coming up row's lead card art (`V2ComingUpRow` hands it up), else the
  first hero pick's (`V2LibraryHome.groundArt`) until the feed answers. The stats line, the library filter
  on the page (Search leaves the bar), the kind control with its make-up bar,
  then F1 (filters-alt.js): All | HD | 4K plus one glass Filter menu with a
  count (Show, Sort, Display, then More filters: recency, group by status,
  combine HD + 4K for admins, and Reset). Set filters show as removable
  tokens under it. Then the Needs-you module (held downloads, files missing
  or unreadable, dead links), the Coming up row, the poster shelf whose
  header is a menu (Recently added, Missing, Needs you, Upcoming; empty ones
  hide), and "All titles" with a glass sort capsule and grid ⇄ list.
- **Coming up** (`App/V2/Screens/Library/ComingUp/`), in place of the hero
  picks: the hero carousel (text title until the server sends a logo) of
  library titles with a release or airing in the window, one card per
  title, soonest first, each saying why ("Digital · Fri", "S2 E5 ·
  tonight"). Six kinds: digital, physical, in cinemas, series premieres,
  season premieres, next episodes (absolute-only anime by its number;
  specials stay out). The header's glass menu offers Mix (digital,
  physical, series premieres, season premieres), Movies only, Series only
  (another mix reads Custom), the kind toggles and a 7 / 14 / 30 day window
  (default 30). Stored under v2-only keys `v2.library.comingUp.kinds` and
  `v2.library.comingUp.days`. Data: `GET /api/v1/calendar`
  (`APIClient.calendar`), cached answer first, refreshed every 10 minutes.
  Nothing in the window falls back to Recently added; the shelf under it
  then shows its next source instead of Recently added again (the stored
  choice stays), or hides when there is none.
- **Posters** (`V2PosterCard`, `V2PosterCaption`): clean art; under it the
  title and one row: the T5 ticket (`EditionBadgeState` from the v1 rails
  plus each version's live download), then Anime, the attention glyph and,
  only for a title switched off, a slashed bookmark + "Off" (owner's monitor
  mark M1, 2026-11-05; monitored shows nothing). Filter › Show › Not
  monitored lists them (v2 key `v2.library.unmonitored`). Attention is an
  orange ring. The grid keeps 24pt clear on its trailing side for the A–Z
  thumb.
- **List, stats, no match**: the compact list rows sit on one W1 surface;
  Library stats is W1 modules on the tint ground (two columns when wide); no
  matches offers Search everything (the words go to the Search tab) and Clear.
- **Layouts**: phone and folded Duo three posters a row, rails running on
  under the column; flat open the grid widens (about 104pt posters, seven
  across) and the kind control and F1 share one line; book pose keeps the
  fold in a gutter (`PosterTracks`).
- **Not built yet**: the network (Service) filter, missing-episodes and
  upgrades shelves (they need the server), logo heroes.

## Title page (slice S5)

- **Wiring**: the shell shows every open title through `TitlePageHost`
  (`App/Screens/Detail/TitlePageHost.swift`), in the sheet and the open
  Duo's column alike. v1 never sets `\.titlePage`, so it keeps
  `ItemDetailView`; `V2RootView` passes `V2TitleView`. Every place that
  calls `model.open(_:)` (the v2 Library, Search, Calendar, the queue, deep
  links) gets the v2 page. With the override set, the shell never splits a
  title at the fold (`titleSpread` and `episodeBeside` are off).
- **Flat open Duo**: `TitlePageOverride.flatOpenListShare` (⅓) makes the
  shell's split one seamless display while a title is open: the list a
  third, the title the rest, no fold gutter. Book pose keeps the pages and
  the gutter. Beside an open title the v2 Library's ground switches to the
  title's palette in the deeper `.listPane` recipe, with no art (it
  crossfades with the palette, not under Reduce Motion).
- **Reused from v1**: `DetailStore` and its loading, the live queue rows,
  v1's child sheets (S6b swaps in v2's Interactive search and Delete, see
  below; the rest stay v1's), the toast,
  the fold / unfold re-host, the poster-menu intents, the More menu
  (`ItemDetailMoreMenu` in its compact form, so it carries every item
  action), the setup and request strips, the release timeline and the
  Files, History, Searches and Collection panes (Seasons is v2's since S6).
- **Screen** (`App/V2/Screens/Title/`): one column on `.v2PageGround` from
  the hero's art (the mesh painted down the whole page, so near-black art
  never leaves the page black). The hero is the textless backdrop with the
  kit's shade; dark palettes darken its foot into the page tint and fade
  into it, light palettes keep the warm dark edge. On the foot: the title
  in white (text until the server sends `logo_url`) and the meta line
  (series: year · genre · certificate · rating; movie: year · certificate ·
  runtime · rating · genres, then the tagline). Then the overview (three
  lines, More), one W1 version card per version (T5 badge, name or
  profile, n/m, one-ink rail, size and state; a tap opens Files at that
  version), Search missing / Search (the one prominent glass button),
  Interactive search (person) and Monitored (bookmark, the Library's bulk
  monitor), Needs you only while a download is held or a version needs
  attention (Review opens it in the Queue, or Files), Next up for a series
  (the latest aired gap within two weeks, else the next to air; series art
  until episode stills arrive), the release timeline for a movie, then the
  tabs as a segmented control. A movie lands on Overview, which is v2's:
  genres, the trailer card, the cast rail, the collection rail and More
  like this.
- **Bar**: Close / Back, then one capsule of Refresh, Edit and More.
- **Not built yet**: logo heroes and the network mark (server), the open
  Duo's two-column title body and the header band across the display when
  the library is hidden (S7), studio logos (no field).

## Season and episode pages, title sheets (slices S6 and S6b)

- **Navigation** (`V2TitleRoute`): seasons and episodes push inside the
  title's `NavigationStack` (both hosts wrap the title in one). The
  destinations are registered on `V2TitleView` and get the store again
  (`V2TitleDestination`). Anything that sets v1's `store.episodeSheet`
  (Next up, the Files tab's gaps, deep links) pushes the episode page
  instead of the v1 sheet.
- **Seasons tab** (`Title/Season/`): `V2SeasonsTab` replaces v1's pane.
  One W1 card per season (`V2SeasonCard`, newest first, Specials last): the
  series poster until season posters exist, "8 episodes · 13 Oct to 10
  Nov", one lane per version (T5 badge, one-ink rail, n/m of aired), what
  is still moving ("1 downloading · 1 held · 1 upcoming"), a chevron. v1's
  numbering check and renumbering banner stay.
- **Season page** (`V2SeasonPage`): on the series' art ground; the bar
  carries "Season 1 / 6 of 7 on disk · 1 upcoming" and the ⋯ menu
  (`V2SeasonActionsMenu`: Search season, Search missing, Search each
  episode, Interactive search; Monitored, Refresh and scan, Sort; Season
  history, Rename preview). Then one tick lane per version
  (`EpisodeTicks`), Search missing (v1's gradual search), and the episode
  rows in a plain list so swipes are the system's: Search and Monitor
  (bookmark). Press and hold adds Interactive search. Sort is v1's
  per-season `oldestFirst`. Actions act on every version, since the page
  shows every version.
- **Episode rows** (`V2EpisodeRow`): the series backdrop as the still until
  the server sends stills (dimmed while not aired), title, "E4 · 48m ·
  Oct 20" (anime adds the absolute number), two lines of overview or "No
  synopsis yet · airs …", one T5 badge per version, and the status circle

  orange pause, accent ring with percent and a held mark).
- **Episode page** (`Title/Episode/`): the art with the episode title in
  white on its foot and "S1 · E4 · Oct 20 '26 · 48m"; Details | History |
  Search. Details: overview, Monitored (bookmark + toggle), the version
  switch (HD | 4K), the shown version's file card (`V2EpisodeFileCard`:
  quality, release name, score, the facts grid from v1's
  `EpisodeFileFacts`, custom formats, path, Copy path, Delete) or its state
  and searches when it has no file, and the history strip (last four
  events, newest last). History: v1's timeline rows for the shown version.
  Search: the v2 interactive search, embedded. Bar: Automatic search,
  Interactive search, and the file's ⋯ (Copy path, Replace, Clean up a
  dead link, Delete, Delete and blocklist).
- **Sheets** (`Title/Sheets/`, `V2TitleSheets`): Interactive search
  (`V2InteractiveSearchSheet` / `V2InteractiveSearchPane` on v1's
  `InteractiveSearchModel`): HD | 4K with the profile and cutoff, v1's
  scope and cooldown strips, a scan card (releases, indexers, accepted),
  v1's passed-over chips, the title filter plus one Filters menu (sort and
  direction, hide rejected / blocklisted, resolution, indexer, protocol,
  reset), and W1 release cards with the reason, ⋯ (Copy name) and Grab.
  Grab anyway opens `V2GrabAnywaySheet` (release, the problem, what
  fusionha will do; Keep the current choice or Grab anyway). Delete is
  `V2DeleteSheet` (each version's folder, files and size, "Also delete the
  files" with the total, red Delete). Edit, Add version and Manage files
  are already native forms in system sheets (the mock's look) and stay
  v1's, as does every other sheet (`DetailActionSheets`).
- **Not built yet**: episode stills and season posters (server), the
  Grab anyway decision's "Blocklist this release" (the blocklist API takes
  a history or download id, which a search result has none of), the open
  Duo's list-beside-episode layout (S7).
